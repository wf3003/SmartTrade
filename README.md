# SmartTrade (量策)

AI 驱动的数字货币合约自动交易系统。基于**技术指标规则引擎** + **DeepSeek AI 方向复核**，支持多交易所、多币种、全自动运行。

## 特性

- **六类行情分级**：强趋势多/空 → 弱趋势多/空 → 震荡偏多/空 → 纯震荡，每级不同杠杆和入场策略
- **动态入场**：靠近均线做反弹/回踩（高置信度），远离均线追入（低置信度）
- **多周期回测策略选择**：实时扫描 5m/15m/30m/1h/4h，自动选择反转或延续策略
- **AI 方向复核**：DeepSeek 每周期校验策略信号方向，不一致时跳过
- **方向分散**：同方向最多 5 个持仓，防单边集中风险
- **超涨超跌保护**：ATR 多倍偏离 + RSI 极端时拦截同方向信号
- **全自动风控**：ATR 动态止损 + 跟踪止盈 + 盈利回吐减半 + 账户回撤保护
- **流水账数据库**：部分平仓 INSERT 新记录，不改原记录状态，防同步逻辑误重建幽灵仓位
- **实时仪表盘**：Web 界面展示持仓、决策、交易记录
- **多交易所**：支持 OKX、Gate.io、Binance（含模拟盘）

## 行情分类与策略

| 行情类型 | ADX 范围 | 杠杆 | 入场方式 | 置信度阈值 |
|---------|---------|------|---------|-----------|
| 强趋势多/空 | ≥40 | 6x (基数) | 回踩/反弹 + 追入 | 35% |
| 弱趋势多/空 | 25-40 | 4x | 回踩/反弹 + 追入 | 40% |
| 震荡偏多/空 | 18-25 | 2x | 仅回踩/反弹（禁止追入） | 55% |
| 纯震荡 | <18 | 不开仓 | — | — |

每周期自动扫描 5m/15m/30m/1h/4h 五个时间框架的回测表现，选出最优策略（反转或延续）。日线 ADX > 50 时强制从反转转为延续策略，ADX ≥ 60 且多空周期矛盾时顺日线方向开仓。

## 风控规则

- **止损**：ATR × 2，范围 [2%, 8%]（基于 1h ATR% 自适应）
- **止盈**：ATR × 4，范围 [4%, 15%]
- **跟踪止盈**：价格峰值 ≥ 0.8% 激活，≥12% 宽松回撤至 25%，≥6% 回撤容忍 1.5× 保底
- **盈利回吐减半**：有过 ≥5% 峰值后转亏，自动减半保本
- **时间止损**：持仓 > 4 小时从未盈利且亏损 ≥ -2%，平仓释放保证金
- **超跌/超涨**：ATR 多倍偏离 + RSI<30/>70，拦截同方向信号（极端趋势 ADX>55 时放过）
- **同方向限制**：最多 5 个同方向持仓
- **持仓上限**：最多 20 个
- **每日亏损**：累计亏损 ≥ $200 暂停交易
- **账户止损**：权益 ≤ $100 平所有仓
- **止损冷却**：递增惩罚 — 第 1 次 30 分钟，第 2 次 1 小时，第 3 次 4 小时
- **行情质量过滤**：1h ATR 趋势 + K 线实体比 + 多周期方向一致性 + 资金费率，综合评分 < 20 跳过信号

## 技术栈

- TypeScript + Node.js + tsx watch
- ccxt（交易所接口）
- DeepSeek API（AI 方向复核）
- SQLite（数据存储，流水账模式）
- Express（Web 仪表盘）

## 技术指标（多时间框架）

每个币种每周期拉取 7 个时间框架（1m / 5m / 15m / 30m / 1h / 4h / 1d）各 60 根 K 线。

**1h 框架（策略入场）**：
- **EMA 20/50** — 趋势方向（日线 ADX>50 时用 EMA20，否则用 EMA50）
- **ADX** — 趋势强度（日线，六类分级）
- **RSI 14** — 超买/超卖
- **ATR** — 波动率（动态止盈止损、入场带宽度、杠杆限制）

**多周期扫描（回测选择策略）**：
- 5m / 15m / 30m / 1h / 4h 各跑一次回测
- 对比反转策略和延续策略的近期准确率
- 选差值最大的时间框架作为本次策略依据

## 数据库流水账模式

所有交易操作遵循"只记录、不覆盖"原则：

- **开仓**：INSERT 一条 status='open' 的记录
- **部分平仓**：INSERT 一条 status='partial_closed' 的减仓记录（带 parent_id 指向原交易），**不修改原记录状态**
- **全平**：INSERT 减仓记录，UPDATE 原记录状态为 closed

交易所同步逻辑始终能匹配到 status='open' 的原记录，不会误补建幽灵仓位。减仓记录不参与胜率、盈亏统计（仅做操作日志）。
